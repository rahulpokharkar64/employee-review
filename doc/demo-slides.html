01 · Scope

Two screens. Four core APIs.

Mandatory screens

  1. Submit review — active employee, Open period, three 1–5 ratings, required comments.
  2. Review register — employee, period, ratings, API average, status.

Required API contract

GET/api/employees
GET/api/review-periods
GET/api/reviews
POST/api/reviews

Identifier detail: create uses numeric employee/period IDs; review filters use employee code (e.g. EMP101) and numeric period ID.

02 · Architecture

Each layer has one job.

React + TypeScript

Routes, form state, reusable components, register filters.

→

FastAPI

Request validation, duplicate/period rules, calculated average.

→

PostgreSQL

Employees, review periods, performance reviews, unique pair constraint.

The API response is the source of truth. The UI renders `average_rating`; it does not submit or invent that value.
